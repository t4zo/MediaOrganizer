# Plano de implementação — v1.1

**Objetivo:** distribuir o app automaticamente pelo GitHub, incluir os episódios especiais (temporada 0) na organização e mostrar quais episódios faltam em cada série.

**Escopo:** três frentes independentes, entregues numa única versão:

1. CI/CD: build e testes a cada push, e Releases automáticas por tag.
2. Episódios especiais (temporada 0).
3. Tela **Coleção** (episódios faltando).

**Fora do escopo:**
- Baixar legendas: fica para a v1.2.
- Assinatura de código: está nas ideias a avaliar do [ROADMAP](../../ROADMAP.md).

---

## Ordem de execução

| Etapa | Entrega | Por quê nesta ordem |
| --- | --- | --- |
| 1 | Workflow de CI (build + testes nos 3 sistemas) | Protege as etapas seguintes: cada PR já roda no Windows, macOS e Linux. |
| 2 | Episódios especiais | Muda regras de nomeação e o fingerprint; é base para a Coleção contar a temporada 0. |
| 3 | Tela Coleção | Reutiliza o scanner, o parser e o TMDb já ajustados. |
| 4 | Workflow de Release + documentação | Fecha a versão; a tag `v1.1.0` publica tudo. |

Cada etapa vira um PR próprio, com os testes passando no CI.

## Etapa 1 — CI (build e testes)

**Arquivo novo:** `.github/workflows/ci.yml`

- **Gatilhos:** `push` em `main` e `pull_request`.
- **Matriz de sistemas:** `windows-latest`, `ubuntu-latest` e `macos-latest`.
- **Passos:**
  1. `actions/checkout@v4`.
  2. `actions/setup-dotnet@v4` com `global-json-file: global.json`.
  3. `dotnet build -c Release -warnaserror`.
  4. `dotnet test --project tests/MediaOrganizer.Core.Tests -c Release`.
- **Cache:** pacotes NuGet com `actions/cache` (chave = hash de `Directory.Packages.props`).
- **Badge** de status do CI no README.

**Riscos a observar:**
- Diferenças de sistema de arquivos aparecem nos testes. Exemplo: troca só de maiúsculas no Linux, que diferencia maiúsculas de minúsculas.
- Se algum teste falhar só no Linux, corrigir no Core (não desativar o teste). `CaseOnlyRenameWorks` e `ConflictDetector` são os mais sensíveis.

**Pronto quando:** o workflow passa nos 3 sistemas no PR desta etapa.

## Etapa 2 — Episódios especiais (temporada 0)

### Comportamento

- Arquivos `S00Exx` já são reconhecidos pelo parser e passam a usar os títulos de `tv/{id}/season/0`.
- **Pasta `Specials`:**
  - Deixa de ser ignorada quando a opção **"Incluir episódios especiais"** estiver ligada (padrão: ligada).
  - Os arquivos continuam onde estão (regra da v1.0).
  - O mesmo vale para pastas `Season 00`/`Season 0`.
- **Especial sem número** (ex.: `Breaking Bad - Pilot Extended.mkv` dentro de `Specials`):
  - Compara o texto do nome com os títulos da temporada 0 (normalização de `MediaMatcher.Normalize`).
  - Se casar, sugere o nome com status *Aviso* ("Especial identificado pelo título; confira") e **desmarcado** por padrão.
- **Especiais desligados:** comportamento idêntico à v1.0.

### Mudanças no Core

**`State/AppSettings.cs`:**
- Novo `IncludeSpecials` (padrão `true`).
- A lista padrão de pastas ignoradas perde `Specials`.
- Configurações já salvas continuam com `Specials` na lista. Por isso, o scanner trata `Specials` à parte: se `IncludeSpecials` estiver ligado, essa pasta não é ignorada mesmo constando na lista.

**`Scanning/LibraryScanner.cs`:**
- Recebe `includeSpecials`.
- Marca os vídeos encontrados em pastas de especiais (`LibraryFolder.SpecialVideos` ou um conjunto de caminhos).

**`Parsing/ReleaseNameParser.cs`:**
- Para arquivos sem marcador dentro de pasta de especiais, `ParseSpecialTitle(name)` devolve o texto limpo:
  - normalizado (2.1 da SPEC);
  - sem tags;
  - sem o nome da série no início.

**`Planning/RenamePlanner.cs`:**
- `S00Exx`: usa `EpisodeTitles` normalmente (a temporada 0 é só mais uma temporada).
- Sem número em pasta de especiais:
  - busca a temporada 0 e escolhe o episódio de maior similaridade (igualdade normalizada, ou um título contido no outro);
  - sem candidato, o arquivo fica *Ignorado* como hoje.

**Seleção inicial:**
- `RenameItem` ganha `bool NeedsConfirmation` (padrão `false`).
- Na App, `ItemViewModel.IsSelected` começa em `IsChange && !NeedsConfirmation`.

**`Scanning/FolderFingerprint.cs`:** `RulesVersion = 2`. Pastas já processadas passam a ser reavaliadas uma vez, para incluir os especiais.

### Mudanças na App

- **Configurações:** checkbox "Incluir episódios especiais (temporada 0)".
- **Prévia:**
  - Itens com `NeedsConfirmation` mostram o aviso.
  - Esses itens só são aplicados se o usuário marcar.

### Testes (`WorkflowTests` + `docs/test-cases.json`)

- `S00E01` renomeado com o título da temporada 0 (FakeTmdb com `season/0`).
- Arquivo sem número em `Specials` casado pelo título fica desmarcado e com aviso.
- Com `IncludeSpecials = false`, a pasta `Specials` é ignorada como na v1.0.
- Configuração antiga com `Specials` em `IgnoredFolders` e `IncludeSpecials = true`: a pasta é incluída.
- Novo caso em `test-cases.json`: `Breaking.Bad.S00E01.Good.Cop.Bad.Cop.720p` → temporada 0, episódio 1.

### Documentação

- SPEC: nova seção "Especiais"; `RulesVersion` 2.
- README: tabela de funcionalidades.

**Pronto quando:** uma pasta `Specials` com arquivos de download é renomeada com os títulos oficiais da temporada 0.

## Etapa 3 — Tela Coleção (episódios faltando)

### Comportamento

- Nova página **Coleção** na barra lateral, entre *Organizar* e *Histórico*.
- **Análise:**
  - Usa a mesma pasta da biblioteca.
  - Só para séries; filmes ficam de fora.
  - Para cada série, compara os episódios presentes com os episódios oficiais **já exibidos**: `air_date` anterior ou igual a hoje.
- **Lista de séries:**
  - Mostra pôster, nome e progresso (ex.: `46/50 episódios`).
  - Selo por série: *Completa*, *Faltando N* ou *Sem correspondência*.
- **Detalhe da série, por temporada:**
  - situação: completa / incompleta / não iniciada;
  - episódios faltando, com número, título e data de exibição;
  - próximos episódios ainda não lançados, com a data.
- Arquivos `S04E01-E02` contam como dois episódios presentes.
- **Especiais:** a temporada 0 aparece separada e não entra no percentual. Um especial faltando não deixa a série "incompleta".
- **Filtros:** *Todas*, *Incompletas*, *Completas*.
- **Exportar:** lista de faltantes em CSV (`série;temporada;episódio;título;data`) ou texto, via `StorageProvider.SaveFilePickerAsync`.
- **Atualizar:** busca os dados ignorando o cache, para séries em exibição.
- **Correspondência:** usa a mesma memorizada pela tela Organizar (`Matches`). Sem correspondência, oferece "Identificar" (o mesmo `MatchDialog`).

### Mudanças no Core

**`Metadata/TmdbModels.cs`:**
- `TvDetails` ganha `IReadOnlyList<TvSeasonSummary> Seasons`, com `SeasonNumber`, `EpisodeCount`, `AirDate` e `Name`.
- `TvEpisode` já tem `AirDate`; adicionar um parse seguro para `DateOnly?`.

**`Metadata/TmdbClient.cs`:**
- Parâmetro opcional `bypassCache` em `GetTvAsync`/`GetSeasonAsync`.
- A resposta nova sobrescreve o cache.

**Novo `Collection/CollectionAnalyzer.cs`:**

```csharp
public sealed record EpisodeRef(int Season, int Episode, string? Title, DateOnly? AirDate);
public sealed record SeasonReport(int Season, int Aired, int Present,
    IReadOnlyList<EpisodeRef> Missing, IReadOnlyList<EpisodeRef> Upcoming);
public sealed record SeriesReport(LibraryFolder Folder, MediaCandidate? Show,
    IReadOnlyList<SeasonReport> Seasons, CollectionStatus Status, string? Message);

IAsyncEnumerable<SeriesReport> AnalyzeAsync(IReadOnlyList<LibraryFolder>, bool refresh, CancellationToken);
```

- Episódios presentes vêm de `ReleaseNameParser.ParseEpisode` sobre `folder.Videos`.
- Títulos seguem a `LanguagePolicy`, reaproveitando a lógica de `EpisodeTitles`. Para isso, extraí-la de `RenamePlanner` para uma classe interna compartilhada.
- "Hoje" vem de um `TimeProvider` injetado, para os testes terem data fixa.
- Paralelismo igual ao `LibraryAnalyzer`: 4 pastas, `Channel`.

**Novo `Collection/CollectionExporter.cs`:** gera o CSV (`;`, UTF-8 com BOM para abrir no Excel) e o texto.

### Mudanças na App

**Arquivos novos:**
- `ViewModels/CollectionViewModel.cs`, `SeriesReportViewModel.cs`, `SeasonReportViewModel.cs`.
- `Views/CollectionView.axaml`, com o mesmo layout de duas colunas da tela Organizar.

**Ajustes:**
- `Page.Collection` + item em `MainWindowViewModel.NavItems` + `DataTemplate` em `App.axaml` + registro no DI.
- `ShellServices.SaveFileAsync(...)`, que encapsula `SaveFilePickerAsync`.
- Ícone novo em `Icons.cs`: checklist (Material Design Icons).

### Testes

- **Série com S01 completa e S02 parcial:** faltantes corretos, com título e data.
- **Episódio com data futura:** vai para *Próximos* e não conta como faltante.
- **Arquivo multi-episódio:** conta como dois presentes.
- **Temporada 0:** não afeta o status da série.
- **Série sem correspondência:** status *Sem correspondência*, sem consultar o TMDb.
- **Exportador CSV:** cabeçalho, separador e escape de `;` nos títulos.

### Documentação

- SPEC: nova seção "Coleção".
- README: funcionalidade + captura de tela (gerada pelo script de snapshots headless).
- ARCHITECTURE: novo módulo `Collection`.

**Pronto quando:** a tela Coleção lista corretamente os episódios ausentes de uma série com temporadas parciais.

## Etapa 4 — Releases automáticas + documentação final

**Arquivo novo:** `.github/workflows/release.yml`

- **Gatilho:** `push` de tags `v*`.
- **Runner:** `macos-latest`. Assim o `codesign` ad-hoc do `.app` funciona, e o cross-compile gera Windows e Linux na mesma máquina.
- **Permissões:** `contents: write`.
- **Passos:**
  1. Checkout + setup-dotnet.
  2. `VERSION=${GITHUB_REF_NAME#v} ./build.sh` (os testes rodam dentro do script).
  3. Empacotar:
     - `MediaOrganizer-windows-x64.exe`: o exe renomeado.
     - `MediaOrganizer-linux-x64.tar.gz`: tar preserva o bit de execução.
     - `MediaOrganizer-macos-arm64.zip` e `MediaOrganizer-macos-x64.zip`: via `ditto -c -k --keepParent`, que preserva o bundle e as permissões.
     - `SHA256SUMS.txt`.
  4. `gh release create "$GITHUB_REF_NAME" <arquivos> --generate-notes`, com `--prerelease` quando a tag contém `-` (ex.: `v1.1.0-rc.1`).

**Ajustes:**
- `build.sh`: aceitar `VERSION` vindo do ambiente (já aceita) e sair com erro se algum alvo falhar (já usa `set -e`).
- README, seção *Download e uso*: nomes dos novos arquivos e instruções para descompactar (`tar -xzf`, duplo clique no `.zip` do macOS).
- BUILDING: seção "Publicando uma versão" (criar a tag `vX.Y.Z` e enviar com `git push --tags`).
- ROADMAP: marcar a v1.1 como ✅.

**Validação:**
1. Enviar a tag `v1.1.0-rc.1` e conferir a pré-release: 4 arquivos + checksums.
2. Baixar e abrir o executável do Windows.
3. Pedir teste manual no macOS e no Linux.
4. Se tudo der certo, criar a tag `v1.1.0`.

**Pronto quando:** criar a tag `v1.1.0` publica os executáveis em Releases sem passos manuais.

## Riscos e decisões em aberto

| Item | Risco | Mitigação |
| --- | --- | --- |
| Especiais casados pelo título | Falsos positivos | Sempre desmarcados por padrão e com aviso; nunca aplicados sem o usuário marcar. |
| `RulesVersion = 2` | Todas as pastas são reavaliadas uma vez | Esperado; com o cache do TMDb, a reavaliação é rápida. Avisar nas notas da versão. |
| Datas de exibição no TMDb | Episódios sem `air_date` | Tratados como "não exibidos" (não contam como faltantes). |
| Limite de requisições do TMDb na Coleção | Bibliotecas grandes fazem muitas chamadas | Cache de 7 dias + limite de 8 requisições simultâneas + resiliência (já existentes). |
| Executáveis não assinados | Avisos do SmartScreen/Gatekeeper | Documentado no README; assinatura fica nas ideias do ROADMAP. |
| Runners do macOS no GitHub Actions | Mais lentos/limitados | Só o workflow de Release usa macOS; o CI roda nos 3, mas só em push/PR. |
